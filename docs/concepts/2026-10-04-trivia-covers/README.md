## Delivery and regeneration

The public cover slug is `trivia`; the game id remains `miro`.
`scripts/optimize-box-covers.mjs` and `scripts/optimize-wide-covers.mjs` read
the selected workspace source paths for `miro`. The other games keep their
existing sibling art-archive convention.

```sh
node scripts/optimize-box-covers.mjs miro
node scripts/optimize-wide-covers.mjs miro
```

Square delivery uses the existing library contract: a 1024 × 1024 WebP at
quality 88 (downsampled from the actual 1254-square source), 640 and 320 square
variants, and a 64 × 1024 left-edge spine. The dedicated wide cover keeps the
source's middle band, `y=256…768`, without stretching: 1536 × 512 and 768 × 256
WebPs at quality 82. Both scripts add their responsive and low-resolution
preview entries to `lib/artwork-previews.json`.

## Verification boundary

Reviewed the new sources, a 160-square thumbnail, the normal 3:1 crop at
390 × 130 and a representative 80% height crop at 390 × 104 (`y=307…717`).
Review images are preserved in `assets/art/trivia/2026-10-04/review/`.
Title spelling, thumbnail readability, key landmark completeness, full-bleed
edges, source opacity and delivery dimensions were checked. The files were
generated by the existing mechanical crop/resize scripts. No art-generation
source was used as an input to another generation.

This artwork pass does not establish browser, touch or setup-layout acceptance;
those belong to the complete Trivia implementation's focused browser checks.
The production allowlist is regenerated after all registry changes, through
`node scripts/production-assets.mjs --write`.
